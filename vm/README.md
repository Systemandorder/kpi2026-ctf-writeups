## Що це за файл

Нативний x64. Перевірка побудована на простому стековому
псевдокоді — своєрідній мінімальній «VM»: кожен крок застосовує один
і той самий ланцюжок операцій до символу флага і порівнює результат
з таблицею еталонних значень.

## Логіка перевірки

reg0 = 0 ; індекс символу
reg2 = 66 ; стартове попереднє значення (prev)
reg3 = 40 ; довжина прапора

цикл:
reg1 = flag[reg0] ; взяти символ прапора за індексом
reg1 = reg1 XOR reg2 ; XOR з попереднім результатом
reg1 = reg1 * 29 (mod 256) ; множення
reg1 = reg1 + 91 (mod 256) ; додавання
reg1 = rol8(reg1, 3) ; циклічний зсув вліво на 3
reg1 = reg1 XOR 0xA7 ; ще один XOR
порівняти reg1 з TABLE[reg0] ; якщо не рівні — позначка помилки
reg2 = reg1 ; наступний prev = поточний результат
reg0 += 1
якщо (40 - reg0) != 0: повторити цикл

## Ключовий момент

Перевірка символу `i` залежить від `prev` — результату попереднього
кроку, а не від попереднього символу флага напряму. Але сам `prev`
на наступній ітерації одразу переприсвоюється як **значення з
таблиці `TABLE[i]`** (а не обчислений `reg1`), тому ланцюжок
насправді не накопичує помилку: кожен крок обертається незалежно,
використовуючи `TABLE[i-1]` як відомий наперед `prev`.

Завдяки цьому рівняння для кожного символу обертається окремо, у
зворотному порядку операцій: XOR → ror → віднімання → множення на
обернений елемент.
