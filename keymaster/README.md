## 📖 Опис завдання

Програма приймає рядок **рівно з 40 символів** і перевіряє його приблизно **120 разів поспіль**, щоразу за новою формулою. Кожна перевірка бере кілька символів введеного рядка, перемножує й додає їх між собою та порівнює результат із конкретним числом, зашитим у бінарник.

- хоч одна перевірка не збіглась → `Wrong.`
- збіглись усі → `Correct!`

По суті, це **система приблизно зі 120 рівнянь із 40 невідомими**, де невідомі це символи прапора. Підібрати розв'язок вручну нереально комбінацій занадто багато.

- У рядках видно: `usage: %s <flag>`, `Wrong length.`, `Correct! The flag is the input you provided.`, `Wrong.`

Отже:

2. Спочатку перевіряється довжина (`Wrong length.`).
3. Далі йде перевірка самого вмісту, а підсумок  `Correct!` або `Wrong.`

## 🧠 Аналіз коду

```bash
objdump -d -M intel keymaster.exe > dump.txt
```

Знайшовши за посиланнями на рядки `Wrong.` / `Correct!` функцію `main`, бачимо плоский ланцюжок однотипних перевірок. Усі помилкові гілки ведуть в один і той самий блок, що друкує `Wrong.`:

```asm
cmp  edx, 0x3127        ; константа, зашита в бінарник
jne  <fail>             ; не збіглось → "Wrong."
```

Кожен блок виглядає приблизно так:

1. завантажуємо кілька байтів введеного рядка з пам'яті;
2. комбінуємо їх: `imul` (множення), `add` (додавання), де-не-де `xor`;
3. порівнюємо підсумок із константою (`cmp reg, imm`);
4. якщо не рівно,то стрибок на `Wrong.`

Тобто кожна така перевірка  одне **поліноміальне рівняння** над символами прапора. Наприклад з реального коду: `x_a * x_b + x_c == 0x3127`.

## 🛠️ Підхід до розв'язання

1. Відкрили бінарник у дизасемблері (`objdump -d`, Ghidra) і знайшли велику функцію з сотнею однотипних перевірок виду «якщо (вираз != число) і помилка».
2. Переписали кожну таку перевірку мовою **Z3** (SMT-розв'язувач систем рівнянь) у вигляді «вираз == число».
3. Попросили Z3 знайти 40 чисел (байтів), які одночасно задовольняють усі ~120 рівнянь. Z3 робить це за секунди  завдяки алгоритмам SMT-солвера, а не перебору.
4. Отримані 40 чисел перетворили на ASCII-символи вийшов прапор.

### Чому саме Z3

- Рівняння **нелінійні** (є добутки змінних), тож звичайна лінійна алгебра не підходить.
- Рівнянь більше, ніж невідомих (~120 проти 40), тому система перевизначена, і розв'язок зазвичай **єдиний**.
- Для операцій над байтами (`*`, `+`, `^`) зручні **бітвектори**.Вони точно моделюють поведінку процесора.

## 💻 Приклад скрипта

> ⚠️ Рівняння нижче ілюстративні. У реальному розв'язку підставляються всі вирази й константи, витягнуті з дизасемблера.

```python
from z3 import BitVec, Solver, sat, And

N = 40
x = [BitVec(f"x{i}", 32) for i in range(N)]
s = Solver()

# друковані ASCII
for xi in x:
    s.add(And(xi >= 0x20, xi <= 0x7E))

# відомий формат прапора
for i, ch in enumerate("kpi2026{"):
    s.add(x[i] == ord(ch))
s.add(x[N - 1] == ord("}"))

# ~120 рівнянь з бінарника (приклад)
s.add(x[3] * x[17] + x[5] == 0x3127)
s.add((x[9] ^ x[21]) + x[4] * x[30] == 0x0B1C)
# ...

if s.check() == sat:
    m = s.model()
    print("".join(chr(m[xi].as_long()) for xi in x))
```
