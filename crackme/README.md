# crackme

**Флаг:** `kpi2026{tls_c4llb4cks_h1de_th3_r34l_c0de}`

## Що це за файл

Звичайний нативний x64, зібраний MinGW/GCC, не запакований.
Запускається як `crackme.exe <флаг>`. Флаг має бути рівно
41 символ.

## На що звернути увагу

- У `main` є виклик виду `(*DAT_14000c030)(символ, індекс)` —
  виклик за адресою, яка зберігається у змінній, а не пряме
  звернення до функції.
- **`.bss`** — секція, яка у файлі порожня (всі нулі), а значення
  з'являються лише під час запуску.
- **TLS callback** — функція, яку Windows викликає до `main`.
  Відладчики та дизасемблери часто її пропускають.
- **`VirtualAlloc` + `VirtualProtect`** — програма виділяє пам'ять,
  кладе туди байти і робить цю пам'ять виконуваною. Ознака коду,
  що генерується на льоту.
- **`IsDebuggerPresent`** — перевірка, чи програму відлагоджують.
  Від результату залежить ключ розшифровки.

## Як це працює

1. `VirtualAlloc` виділяє пам'ять.
2. `IsDebuggerPresent` визначає ключ: без відладчика — `0x9e`,
   з відладчиком — `0x61`.
3. 32 байти з `.rdata` (`0x140009070`) XOR'яться цим ключем і
   копіюються у виділену пам'ять.
4. `VirtualProtect` робить пам'ять виконуваною.
5. Адреса цієї пам'яті записується у `DAT_14000c030`.

Розшифрований код:
```asm
movzx eax, cl         ; eax = символ c
movzx r9d, dl         ; r9d = індекс i
imul  r9d, r9d, 0x11  ; i * 0x11
xor   eax, r9d        ; c ^ (i*0x11)
and   eax, 0xff
rol   al, 5           ; циклічний зсув вліво на 5
xor   al, 0xc3
ret
```

`main` порівнює. У циклі `f(ввід[i], i)` звіряється з байтом
еталону з `0x140009040` (41 байт). Якщо хоч один не збігся —
виводиться `Wrong.`.
