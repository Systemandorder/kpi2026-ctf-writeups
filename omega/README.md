# omega

**Флаг:** `kpi2026{st4ck_vm_plus_lfsr_and_sb0x_1s_th3_f1n4l_b0ss}`

## Що це за файл

Нативний x64 (MinGW), не запакований. Найскладніший файл набору:
замість готової формули перевірки, `main` викликає **власний
інтерпретатор байткоду** — свою маленьку віртуальну машину (VM).

## Як влаштована VM

- **Інтерпретатор** — функція `0x140001480`. Вона не містить логіку
  перевірки напряму, лише «двигун»: читає одну команду за одною і
  виконує її.
- **Програма цією мовою** — окремий набір байтів у `.rdata` за
  адресою `0x1400091e0`. Саме ці байти й містять справжню логіку
  перевірки флага.

У двигуна є:
- **Стек** — область пам'яті для тимчасових чисел.
- **~20 команд (опкодів)**: покласти число на стек, зняти, скласти,
  порівняти.
- **Вказівник на поточну позицію** в масиві `0x1400091e0`.

## Причому тут LFSR

**LFSR** — простий генератор псевдовипадкових чисел: зсуваєш біти
числа, і якщо певний біт був одиницею — робиш XOR із заданою
константою. Тут старт — `0xace1`, константа — `0xb400`.

Ключова хитрість: генератор продовжує працювати впродовж усієї
програми, і в нього підмішуються вже оброблені символи флага. Тобто
значення, з яким звіряється п'ятий символ, залежить від того, якими
були символи 0–4. Не можна перевірити пізніший символ, не знаючи
попередніх.

## Чому розв'язано через емуляцію

Замість того щоб вручну розбирати всі ~20 команд двигуна, реальний
код `0x140001480` запущено як «оракул» через **Unicorn Engine**:

1. Завантажуємо секції файлу в пам'ять емулятора за їхніми реальними
   адресами.
2. Кладемо рядок-кандидат (пробний флаг) у пам'ять, адресу пишемо в
   `RCX` (перший аргумент за угодою Windows x64).
3. На стек кладемо фіктивну адресу повернення, щоб емуляція акуратно
   зупинилась після `ret`.
4. Ставимо хук прямо перед інструкцією порівняння (`0x140001576`,
   перед `cmovne`) — видно, які два числа звіряються і чи збіглись
   (прапорець `ZF`).
5. Запускаємо емуляцію з адреси `0x140001480`.
6. Дивимось на регістр `EAX` (1 — флаг вірний, 0 — ні) і на список
   усіх порівнянь по порядку.

Оскільки перевірка символу `i` залежить тільки від уже знайдених
символів `0..i-1`, флаг підбирається послідовно зліва направо: для
кожної позиції перебираються друковані ASCII-символи, поки саме та
перевірка не пройде.
