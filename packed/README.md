**Флаг:** `kpi2026{rc4_str34m_c1ph3r_und3r_a_upx_sh3ll}`

## Що це за файл

Звичайний нативний x64, але **запакований UPX**. Перша ознака —
всього 3 секції замість звичайних 10 (`UPX0/UPX1/UPX2`), з них одна
навіть порожня у файлі.

## Як розпакувати

```bash
upx -d packed.exe -o unpacked.exe
```

Після цього файл стає звичайним 10-секційним PE, і далі працюємо
з ним як зі звичайним бінарником.

## Логіка перевірки (після розпакування)

1. Будується **S-box з 256 байт** через SSE-інструкції (`paddd`,
   `punpcklwd`, `packuswb`) — це просто швидкий векторизований спосіб
   заповнити масив числами `0..255`.
2. **KSA** (ініціалізація ключем): `j = (j + S[i] + key[i % 16]) & 0xff; swap(S[i], S[j])`,
   виконується 256 разів. Ключ — 16 байт, у рядках видно відкритим
   текстом: `Super_Secret_K9y`.
3. **PRGA** (генерація потоку): `i++; j += S[i]; swap; K = S[(S[i]+S[j]) & 0xff]`,
   і одразу `xor` з байтом введеного флага.
4. Результат порівнюється (`memcmp`) з еталоном з `.rdata`.

Це класичний **RC4**.

## Як розпізнати RC4 за виглядом коду

| Ознака | Що означає |
|---|---|
| Масив 256 байт, заповнюється `0..255` | S-box |
| Цикл рівно 256 разів: `j = (j+S[i]+key[i%len]) & 0xff; swap` | KSA |
| Другий цикл: `i++; j+=S[i]; swap; K=S[(S[i]+S[j])&0xff]` | PRGA |
| `xor` результату з вхідними даними | сам шифр — потоковий XOR |

## Рішення

RC4 — потоковий шифр, сам собі обернений: щоб отримати флаг, не
треба нічого «відміняти», достатньо згенерувати той самий keystream
(знаючи ключ) і зробити XOR з еталоном з файлу.
